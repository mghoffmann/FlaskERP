# 00 — Architecture & Conventions

Part of [Shopfloor ERP requirements](README.md). Every other document assumes the conventions defined here.

## Stack

- Python 3.12, Flask 3.x
- SQLAlchemy 2.x (declarative models), Flask-Migrate (Alembic) for migrations
- PostgreSQL 16, driver `psycopg[binary]` (psycopg 3)
- gunicorn in containers; `flask run --debug` for local dev
- pytest for tests; no frontend build tooling of any kind

## Flask conventions

- **App factory**: `create_app(config_name)` registers extensions, blueprints, error handlers, and CLI commands. `SECRET_KEY` and `DATABASE_URL` come from the environment; the app refuses to start in production without a real `SECRET_KEY`.
- **Blueprints**: one per module, all under `/api`. Static frontend served by Flask's static handling with `static_url_path=""` so `/parts.html` works; `/` redirects to `/index.html`.
- **Sessions**: Flask's default signed-cookie session. Set `SESSION_COOKIE_HTTPONLY=True`, `SESSION_COOKIE_SAMESITE="Lax"`, and `SESSION_COOKIE_SECURE=True` in production.
- **CSRF**: not implemented (JSON-only API + SameSite=Lax cookies is acceptable for a demo). Note this tradeoff in the repo README — knowing it exists is part of the demo.
- **No global state**: request handlers get the DB session via `db.session`; each request is one transaction — commit on success, roll back on error (register a teardown handler).

## API conventions

- All endpoints under `/api`; JSON in, JSON out (`Content-Type: application/json`).
- Route paths kebab-case (`/api/work-orders`); JSON keys snake_case.
- IDs are integers. Timestamps are ISO-8601 UTC strings (`2026-08-17T14:30:00Z`). Quantities and money are JSON numbers (demo-acceptable; a production system would use string decimals).
- List endpoints return `{"items": [...]}`. No pagination except where a doc says otherwise (demo scale).
- Successful create returns `201` with the created object; update returns `200` with the updated object; actions/transitions return `200` with the updated object; logout and similar return `204` empty.

## Error format

Every error response has this shape:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Human-readable summary.",
    "field_errors": {"sku": "SKU already exists."},
    "details": []
  }
}
```

`field_errors` and `details` appear only when relevant.

| HTTP | code | When |
|---|---|---|
| 400 | `validation_error` | Bad/missing fields; `field_errors` maps field → message |
| 401 | `unauthenticated` | No valid session |
| 403 | `forbidden` | Valid session, insufficient role |
| 404 | `not_found` | Unknown ID or route |
| 409 | `invalid_transition` | Document is not in a status that allows this action |
| 409 | `insufficient_stock` | Completion/shipping would drive stock negative; `details` lists shortfalls (see [05](05-work-orders.md)) |
| 409 | `conflict` | Other uniqueness/state conflicts (e.g. duplicate SKU is 400 `validation_error`; deleting a part referenced by an open document is 409 `conflict`) |
| 500 | `internal_error` | Unhandled exception (generic message; never leak stack traces) |

Register JSON error handlers for 404/405/500 so API consumers never receive Flask's HTML error pages.

## Configuration (environment variables)

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes | e.g. `postgresql+psycopg://erp:erp@db:5432/erp` |
| `SECRET_KEY` | yes (prod) | Session signing; dev default allowed only in dev config |
| `SEED_ADMIN_PASSWORD` | no | Password for the seeded `admin` user (default `admin123` in dev only) |
| `SEED_OPERATOR_PASSWORD` | no | Same for `operator` user |
| `DOMAIN` | prod only | Public hostname, used by Caddy (see [11](11-deployment.md)) |

`.env.example` documents all of these; `.env` is gitignored.

## Acceptance criteria

- `flask run` against the dev compose database serves both `/api/dashboard` (after login) and the static pages.
- Hitting an unknown API route returns the JSON error format, not HTML.
- An exception in a handler rolls back the transaction and returns the 500 JSON shape.
- Grepping the codebase for `qty_on_hand` shows writes only inside `app/services/stock.py`.
