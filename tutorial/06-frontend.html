How the HTML and JavaScript relate to the Python

A deliberately framework-free frontend — what Angular gives you, done with the platform.

The architecture in one picture

Angular world                        This project
─────────────                        ────────────
SPA: one index.html, client router   Multi-page: one real HTML file per screen
Components + templates               One ES module per page (js/parts.js, js/part.js, ...)
HttpClient + interceptors            fetch(), wrapped once in api()
JWT in header, auth interceptor      Session cookie — browser attaches it automatically
npm + webpack/vite build step        NO build step — files served exactly as written
Angular sanitizes template bindings  el() helper builds DOM nodes; innerHTML banned

The relationship to Python is minimal by design: Flask serves the frontend as plain static files (static_url_path="" puts app/static/parts.html at /parts.html) and answers fetch() calls under /api/*. There is no server-side templating — Flask never generates HTML. Jinja (Flask's Razor) exists and is the classic Flask approach; this project deliberately skipped it, so the boundary between backend and frontend is a JSON contract, exactly like your Angular + Web API projects — the frontend just isn't compiled.

Each page is: HTML skeleton + one module

<!-- app/static/parts.html (trimmed) -->
<body>
  <header class="app-header">...shared nav, user chip...</header>
  <main>
    <div class="page-header-actions" data-role="admin">
      <button id="new-part-btn" class="btn">New part</button>
    </div>
    <table id="parts-table">...</table>
  </main>
  <script type="module" src="/js/parts.js"></script>
</body>

// app/static/js/parts.js (shape of every page module)
import { el, api, toast, qs, setQs, initShell } from "./app.js";

const user = await initShell();          // auth check + shared header + role gating
if (user) {                              // (no top-level return in ES modules)
  main();
}

async function main() {
  const data = await api("GET", "/api/parts" + location.search);
  renderTable(data.parts);               // build rows with el(), append to the table
  const newBtn = document.getElementById("new-part-btn");
  if (newBtn) newBtn.addEventListener("click", openNewPartModal);   // null-guard! see below
}
Map it to Angular: app.js ≈ the shared CoreModule + AppComponent shell; initShell() ≈ the auth guard + layout render; each page module ≈ a routed component's ngOnInit; and navigation between screens is real browser navigation (full page load) instead of client routing. For an ERP where every screen is a fresh data fetch anyway, the SPA machinery buys little — that's the tradeoff argument for skipping the framework in a demo this size.

api() — the HttpClient + interceptor, in 30 lines

Every request goes through one wrapper in app.js (real code, trimmed):

export async function api(method, path, body) {
  const opts = { method, credentials: "same-origin", headers: {} };
  if (body !== undefined) {
    opts.headers["Content-Type"] = "application/json";
    opts.body = JSON.stringify(body);
  }
  const res = await fetch(path, opts);
  if (res.status === 204) return null;
  const payload = await res.json().catch(() => null);
  if (res.ok) return payload;

  if (res.status === 401 && !location.pathname.endsWith("/login.html")) {
    location.href = "/login.html";               // ≈ auth interceptor redirect
  }
  const errBody = (payload && payload.error) || {};
  throw new ApiError(res.status, errBody.code, errBody.message,
                     errBody.field_errors, errBody.details);
}

Callers get clean data or a typed ApiError carrying the backend's error envelope — so a form can map field_errors onto inputs and a 409 can show its details list. That's the client half of the error contract from page 2; the two were designed as one.

Authentication: the cookie does the work

Login is POST /api/login; Flask sets a signed session cookie (HttpOnly, Secure in prod). After that, the browser attaches it to every same-origin request automatically — no token storage, no Authorization header, no refresh logic. initShell() calls GET /api/me on page load: 200 means logged in (and returns {id, username, role}), 401 means api() redirects to the login page.

≈ classic ASP.NET cookie authentication rather than the JWT pattern you'd use with Angular. Because the frontend and API share one origin, CORS never comes up, and the usual reason for JWTs (multiple clients/origins) doesn't exist. The cookie is signed with SECRET_KEY (tamper-proof, contents readable-if-decoded like a JWT), holds only the user ID, and the user is re-loaded from the database per request — so a deactivated user dies on the next request, which stateless JWTs get wrong by default. Worth saying in the interview.

Role gating: the server enforces, the UI tidies

Admin-only controls are marked in HTML with data-role="admin". For operators, initShell() removes those nodes from the DOM entirely (not just hides them). Authorization is still enforced server-side by @require_login(role="admin") — the DOM removal is UX, not security; a devtools-savvy operator who re-creates the button still gets a 403.

Removed-not-hidden gating has a sharp edge: page code that does document.getElementById("edit-part-btn").addEventListener(...) crashes for operators, because the element is gone and getElementById returned null — and one uncaught exception kills the module's whole main(), blanking the page. Every gated element reference must be null-guarded (if (btn) btn.addEventListener(...)). This exact bug shipped on the part-detail page and was fixed post-launch — an honest "a bug I shipped and what it taught me" story: the fix was the guard, the lesson is that role-dependent DOM makes every element lookup conditional. Angular's *ngIf has the same removed-not-hidden semantics; the framework just prevents you from holding stale references to it.

el() — safe DOM building instead of templates

With no template engine, pages build DOM with one helper (real code, trimmed):

export function el(tag, attrs = {}, children = []) {
  const node = document.createElement(tag);
  for (const [key, value] of Object.entries(attrs)) {
    if (key === "class") node.className = value;
    else if (key.startsWith("on")) node.addEventListener(key.slice(2), value);
    else if (key in node) node[key] = value;
    else node.setAttribute(key, value);
  }
  for (const child of [].concat(children)) {
    node.appendChild(child instanceof Node ? child : document.createTextNode(String(child)));
  }
  return node;
}

// usage — a table row for a part:
el("tr", {}, [
  el("td", {}, part.sku),
  el("td", {}, part.name),
  el("td", { class: "num" }, fmtQty(part.qty_on_hand)),
])

Note the last line of the child loop: strings become text nodes, never markup. innerHTML with data in it is banned in this codebase — that one rule is the XSS defense. A part named <img src=x onerror=...> renders as literal text.

Angular gives you this for free — {{ interpolation }} auto-escapes and [innerHTML] goes through a sanitizer. Without a framework you must choose the safe primitive yourself; el() makes the safe way also the convenient way, which is the actual trick.

Deep-linkable state via the query string

Filters and searches round-trip through the URL: changing a filter calls setQs({type: "raw"}) (History API, no reload), and page load reads location.search to restore state — so a filtered view is a shareable, refreshable URL. ≈ Angular's queryParams + router navigation, done with two 10-line helpers. Modals are the native <dialog> element (openFormModal() in modal.js) — no Angular Material needed.

The framing for "why no Angular/React?": "It's a scope decision, not an ideology. Eight CRUD-ish screens, one shared shell, no offline or real-time requirements — a framework buys me a build pipeline and a dependency tree, and costs the reviewer the ability to open a .js file and read exactly what runs. For this size I chose the platform; I'd reach for a framework at the point of shared mutable client state across screens." Knowing where the line is matters more than which side of it you stood on.
